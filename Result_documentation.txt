SCRATCH IMPLEMENTATION & FUNDAMENTAL TENSOR MECHANICS (CPU AUDIT)
--------------------------------------------------------------------------------
Environment: Windows 11, Intel Core i7, Iris Xe, 16 GB RAM, Python 3.13.1, PyTorch 2.14.0+cpu

1. Tokenization Ingestion Telemetry:
   - Source Corpus: content.txt (Erasmus Thorne Story)
   - Raw Metrics: 802 words | 5,198 characters
   - BPE Tokenizer: GPT-2 byte-level BPE (`r50k_base` via `tiktoken`)
   - Output Representation: 1,072 discrete token IDs
   - First 8 Ingested Tokens:
     T1: 33 ('B') | T2: 1734 ('ene') | T3: 776 ('ath') | T4: 257 (' a') |
     T5: 44379 (' bruised') | T6: 290 (' and') | T7: 45725 (' violet') | T8: 6766 (' sky')
     Target (T9): 11 (',')

2. Mathematical Verification of Core Operators:
   - Embedding Lookup: Looked up row 33 from `nn.Embedding(50257, 64)`. Tensor values were not
     bounded in [-1, +1] (e.g., initial extremes reached -2.0970 and +3.4489).
   - Positional Encoding Addition: Verified vector addition `X = token_vectors + position_vectors`.
     T1 dim 0: -1.4863 (token) + (-0.4928) (pos) = -1.9791.
   - Attention Projection & Dot Products:
     Calculated Q, K, V via linear projection. Dot product scores for T1 across T1..T8 produced
     extreme magnitudes prior to scaling (-1779.24 to +755.02) due to initial standard normal weights.
   - Scaled Dot-Product Attention:
     Dividing by sqrt(d_k) = sqrt(16) = 4 (or sqrt(64)=8) damped scores before Softmax.
   - Causal Attention Masking:
     Applied `torch.tril(torch.ones(T, T))` filled with `-inf` on upper triangle.
     Guaranteed position T1 attended strictly to position T1 (Softmax weight = 1.000000).

3. The Unused Projection Bug & Architecture Ablation:
   - Defect Identified: Code computed `projected_output = output @ Wo`, but subsequent residual
     lines evaluated `output = output + residual`, completely bypassing `Wo`.
   - Resolution: Corrected dataflow to `output = projected_output + residual`, ensuring full gradient
     flow through output projection weights.

TOY VOCABULARY EXPERIMENT: THE 568-TOKEN ABLATION (TINYGPT-0.12M)
--------------------------------------------------------------------------------
Motivation:
Evaluating 50,257 logits over 128 positions per batch on a CPU caused compute saturation.
An ablation was executed by re-mapping only the 568 unique tokens present in `content.txt`
to compact contiguous indices [0..567].

Configuration:
  - Vocabulary:          568 unique story tokens
  - Model Dimension:     d_model = 64, Context = 8, Heads = 4, Layers = 1
  - Total Parameters:    122,944 (0.12M)

  Step  200 | Train Loss: 2.6461 | Val Loss: 6.1605  <-- Val loss inflection point
  Step  400 | Train Loss: 1.1199 | Val Loss: 7.3744
  Step  800 | Train Loss: 0.3182 | Val Loss: 8.3182

  Step 1600 | Train Loss: 0.2174 | Val Loss: 8.9376

Pruning the vocabulary to in-corpus tokens proved mathematically that parameter count alone does

enable transfer and downstream retrieval tasks.

EOS TOKEN HANDLING & GENERATION TERMINATION AUDIT
--------------------------------------------------------------------------------
Tokenizer Setting: Tiktoken GPT-2 BPE (`enc.eot_token` = 50256, `<|endoftext|>`)

Ablation on Model Termination:
  1. The Silent Continuation Defect: In early test iterations, model generation ran until hitting
     `max_new_tokens=150`, producing repetitive loops of story text.
  2. Training Integration: Added `tokens.append(50256)` directly to training text, presenting exactly
     one EOS transition at sequence terminus.
  3. Generation Detection: Wrapped the sampling loop with explicit termination detection:
     `if next_token.item() == EOS_TOKEN_ID: break`.
  4. Empirical Finding: Due to having only 1 single EOS instance across 1,072 training tokens, the
     model rarely assigned dominant probability mass to token 50256 mid-sentence, defaulting to
     `MAX_GENERATION_TOKENS` cutoff unless explicitly given instruction-formatted datasets.

Key Scientific Takeaways:
1. The Parameter-to-Token Ratio Trap:
   In TinyGPT-6.84M and 15.3M, the ratio was inverted (6.8M params on 1k tokens = 0.00015 tokens/param;
   15.3M params on 143k tokens = 0.0093 tokens/param). In comparison, modern pretraining targets
   >= 20 tokens per parameter. The 500M model training resolved this by processing 131M tokens.
2. Embedding Weight Dominance:
   At 6.84M and 15.3M, embedding matrices accounted for 94.09% and 84.08% of all parameters.
   Only at the 500M scale did attention and MLP compute capacity expand to consume 79.4% of weights.
3. The Role of Checkpoint Restoration:
   Automatic checkpoint restoration at the validation loss inflection point (Step 750 on the 15.3M model)
   prevented saving catastrophic overfit states, providing an essential template for the 500M pipeline.

  1. Software BF16 Emulation: PyTorch 2.11 falsely reported native BF16 on Turing (sm_75).

  1. Precision: Enforced compute capability check (major >= 8) for native BF16.

  2. Memory Reduction: Enabled Gradient Checkpointing (recomputes layer activations on backward pass),
     reducing activation VRAM from ~5.0 GB down to ~0.4 GB.
  3. Batch Geometry: Set micro_batch_size = 1, gradient_accumulation_steps = 64 (same 65,536 tokens/step).
